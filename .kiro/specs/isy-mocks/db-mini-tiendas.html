Ingeniería inversa del módulo Mini Tiendas + su relación con profiles · PostgreSQL

PK primaria FK foránea U única IX índice Todas las tablas llevan auditoría: created_at, created_by, updated_at, updated_by.
Enumerados
stock_status: available · sold_out · made_to_order delivery_option: pickup · delivery · shipping payment_method: cash · transfer · card product_status: draft · published

Diagrama ER

Una Mini Tienda pertenece a un perfil vendedor (profiles). El detalle de profiles es del módulo Perfiles (pendiente); aquí solo se muestra la relación.

erDiagram
    profiles ||--o| mini_stores : "perfil vendedor · tiene"
    mini_stores ||--o{ store_sections : "organiza"
    mini_stores ||--o{ store_products : "ofrece"
    store_sections ||--o{ store_products : "agrupa (opcional)"

    profiles { uuid id PK
               profile_type type
               uuid user_id FK }
    mini_stores { uuid id PK
                  uuid seller_profile_id FK
                  varchar name
                  varchar category
                  text logo_url
                  bool is_open }
    store_sections { uuid id PK
                     uuid store_id FK
                     varchar name
                     int position }
    store_products { uuid id PK
                     uuid store_id FK
                     uuid section_id FK
                     numeric price
                     product_status status
                     stock_status stock }

Tablas

profiles (referencia — módulo Perfiles)

No se define aquí; solo se usa como destino de la relación. La Mini Tienda apunta al perfil vendedor dueño mediante seller_profile_id → profiles.id.
